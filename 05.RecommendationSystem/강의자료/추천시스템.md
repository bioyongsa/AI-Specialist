## 1. 추천시스템이란?

> "사용자가 좋아할 만한 것을 미리 골라서 보여주는 시스템"

### 비개인화 추천 vs 개인화 추천

| 구분 | 방식 | 예시 |
|------|------|------|
| **비개인화** | 모두에게 동일한 추천 | 베스트셀러, 인기 급상승, 최신 업로드 |
| **개인화** | 사용자마다 다른 추천 | 쿠팡 "오늘의 쇼핑 제안", 넷플릭스 "취향저격" |

```
[비개인화] 
  모든 사용자 ──────────────► [인기 상품 TOP 10]

[개인화]
  사용자 A ────────────────► [로맨스 영화]
  사용자 B ────────────────► [SF 영화]
  사용자 C ────────────────► [액션 영화]
```

### 개인화 추천의 두 가지 큰 방향

```
                    ┌──────────────────────────┐
                    │   개인화 추천시스템        │
                    └──────────┬───────────────┘
                               │
              ┌────────────────┴────────────────┐
              ▼                                 ▼
   ┌─────────────────────┐         ┌──────────────────────┐
   │  콘텐츠 기반         │         │  협업 필터링           │
   │ (Content-based)     │         │ (Collaborative        │
   │                     │         │  Filtering)           │
   │ "아이템의 특성을     │         │ "다른 사람들의         │
   │  분석한다"          │         │  행동 패턴을 본다"    │
   └─────────────────────┘         └──────────────────────┘
              │                                 │
              └────────────────┬────────────────┘
                               ▼
                   ┌─────────────────────┐
                   │  하이브리드 (Hybrid) │
                   │  둘 다 활용!         │
                   └─────────────────────┘
```

## 2. 핵심 개념: Utility Matrix

### Utility Matrix란?

사용자(User)와 아이템(Item) 간의 **선호도**를 표로 나타낸 것.

- 값의 범위: 1~5 별점, 좋아요/싫어요, 구매 여부 등
- **대부분의 값은 비어있음 (sparse)** → 추천의 핵심 과제

```
            HP1  HP2  HP3  TW   SW1  SW2  SW3
           ┌────┬────┬────┬────┬────┬────┬────┐
사용자 A   │    │    │    │    │ 4  │    │    │
           ├────┼────┼────┼────┼────┼────┼────┤
사용자 B   │    │    │    │    │ 5  │    │ 5  │  ← SW(스타워즈) 팬
           ├────┼────┼────┼────┼────┼────┼────┤
사용자 C   │    │    │    │    │ 5  │ 1  │    │
           ├────┼────┼────┼────┼────┼────┼────┤
사용자 D   │    │ 5  │ 4  │    │    │    │ 3  │  ← HP(해리포터) 팬
           └────┴────┴────┴────┴────┴────┴────┘
                             ↑
                    빈칸 = 아직 보지 않음
                    (싫다는 뜻이 아님!)
```

### 피드백 수집 방식

| 종류 | 설명 | 장점 | 단점 |
|------|------|------|------|
| **명시적 피드백** (Explicit) | 사용자가 직접 별점/좋아요 입력 | 정확한 선호 반영 | 데이터 양이 적음 |
| **암묵적 피드백** (Implicit) | 클릭, 구매, 시청 기록 등 행동 유추 | 데이터 풍부 | 싫어서 안 본 건지 몰랐던 건지 구분 어려움 |

## 3. 콘텐츠 기반 모델 (Content-based)

### 핵심 아이디어

> "사용자가 좋아했던 **아이템의 특성**과 유사한 아이템을 추천한다"

### 동작 과정

```
① 아이템 프로파일 생성
   영화 "인터스텔라"
   ┌────────────────────────────────┐
   │ 장르: SF                       │
   │ 감독: 크리스토퍼 놀란            │
   │ 주연: 매튜 맥커너히              │
   │ 키워드: 우주, 시간여행, 가족     │
   └────────────────────────────────┘

② 사용자 프로파일 구성
   (사용자가 좋아한 영화들의 특성 집계)
   ┌────────────────────────────────┐
   │ 선호 장르: SF ★★★★★            │
   │ 선호 감독: 크리스토퍼 놀란       │
   │ 선호 키워드: 우주, 미스터리     │
   └────────────────────────────────┘

③ 매칭 → 추천
   "덩케르크" (크리스토퍼 놀란, 전쟁) → 추천!
   "어벤져스" (마블, 히어로) → 덜 추천
```

### 아이템 프로파일 생성 방법: TF-IDF

텍스트 기반 아이템(뉴스, 블로그 등)에서 중요한 단어를 찾는 방법:

```
TF (Term Frequency)   = 특정 문서에서 단어가 나온 빈도
IDF (Inverse Doc Freq) = 전체 문서에서 희귀한 단어일수록 높은 가중치

                    흔한 단어       희귀한 단어
                   "the", "and"    "인터스텔라"
TF-IDF 점수:           낮음 ◄───────────────► 높음
```

### 장단점

```
✅ 장점
   - 다른 사용자 데이터 불필요 (신규 서비스도 가능)
   - 독특한 취향을 가진 사용자에게도 추천 가능
   - 새로운 아이템도 바로 추천 가능
   - 추천 이유 설명 가능 ("감독이 같아서 추천했어요")

❌ 단점
   - 좋은 특성 추출이 어려움
   - 신규 사용자는 프로파일이 없어 추천 불가 (Cold Start)
   - 과특화(Overspecialization): 항상 비슷한 것만 추천
     예) SF만 본 사람에게 SF만 계속 추천 → 다양성 없음
```

## 4. 협업 필터링 (Collaborative Filtering)

### 핵심 아이디어

> "**나와 비슷한 취향의 사람들**이 좋아하는 것을 추천한다"  
> 아이템의 내용(특성)은 전혀 보지 않는다!

```
      나 (사용자 A)                 비슷한 사람들
      ┌───────────┐                ┌───────────┐
      │ ★★★★ 인터│     비슷한!     │ ★★★★ 인터│
      │ ★★★  덩케│  ◄──────────► │ ★★★  덩케│
      │ ?     테넷│                │ ★★★★ 테넷│
      └───────────┘                └───────────┘
                                          │
                                    "테넷 좋아하더라"
                                          │
                                          ▼
                                   → 나에게 "테넷" 추천!
```

### 두 가지 방식

#### (1) User-User 협업 필터링

나와 **비슷한 사용자**를 찾아서 추천

```
[유사도 계산]

사용자 A: [4, -, -, -, 5, -, -]
사용자 B: [-, -, -, -, 5, -, 5]  ← A와 비슷?
사용자 C: [-, -, -, -, 5, 1, -]  ← A와 비슷?
사용자 D: [-, 5, 4, -, -, -, 3]  ← A와 다름

A와 B가 가장 유사 → B가 본 SW3(5점)을 A에게 추천!
```

**유사도 측정 방법:**

| 방법 | 계산 방식 | 특징 |
|------|----------|------|
| **Jaccard 유사도** | 공통 평가 아이템 수 / 전체 평가 아이템 수 | 별점 값은 무시 | -> 공통적으로는 선택했으나, 취향은 서로 반대다(?)
| **코사인 유사도** | 벡터의 각도 (방향 유사성) | 평점 크기 반영, 0점=안본것 문제 | -> 비어있는 값은 뭘로 채워야?? 0이면 '최악'의 평점이므로 문제
| **피어슨 상관계수** | 평균 중심화 후 코사인 | 사용자 평가 기준 차이 보정 |

```
[평점 예측 공식]

                    Σ (유사도 × 이웃의 평점)
r̂(사용자u, 아이템i) = ─────────────────────────
                          Σ |유사도|

→ 나와 비슷할수록 더 큰 가중치!
```

#### (2) Item-Item 협업 필터링

**유사한 아이템**을 찾아서 추천 (아마존의 "이 상품을 산 고객이 함께 구매한 상품")

```
아이템 관점:
"인터스텔라"를 본 사람들이
"덩케르크"도 많이 봤다
    →  인터스텔라 ≈ 덩케르크 (유사 아이템)
    →  인터스텔라를 본 사용자에게 덩케르크 추천!
```

#### User-User vs Item-Item 비교

```
                   User-User        Item-Item
정확도              보통             보통 (조금 더 안정적)
장점                새 아이템에 강함  아이템 수가 유저 수보다 적을 때 유리
단점                사용자 변동이 큼  새 아이템에 취약
실무 선호도         ☆☆☆             ★★★ (아이템이 더 안정적)
```

### 협업 필터링 장단점

```
✅ 장점
   - 아이템 특성(장르, 내용 등) 몰라도 됨
   - 의외의 취향 발견 가능 (Serendipity)

❌ 단점
   - 데이터 부족 시 성능 저하 (Cold Start)
   - 새로운 아이템은 추천 불가 (아무도 본 적 없으니까)
   - 독특한 취향의 사람에게는 유사 사용자 없음
   - 인기 아이템 편향 (popular bias)
```

## 5. 잠재 요인 모델 (Latent Factor Models)

### 핵심 아이디어

> Utility Matrix를 **잠재 요인(Latent Factor)**으로 분해한다

협업 필터링의 행/열을 그대로 쓰는 대신,  
더 압축된 **저차원 벡터**로 사용자와 아이템을 표현한다.

### UV 분해 (UV Decomposition: Matrix Factorization)

```
       [영화들]
        HP1 HP2 SW1 SW2
       ┌───┬───┬───┬───┐
사용자A│ 5 │ 2 │ 4 │ 3 │        [잠재 요인 k=2]
사용자B│ 3 │ 1 │ 2 │ 1 │   ≈    U          ×    Vᵀ
사용자C│ 2 │   │ 3 │ 4 │
사용자D│ 2 │ 5 │ 4 │ 5 │
       └───┴───┴───┴───┘

[R: 사용자×영화]  ≈  [U: 사용자×k]  ×  [Vᵀ: k×영화]

    사용자 벡터 u_A = [판타지 선호도, SF 선호도]
    아이템 벡터 v_HP1 = [판타지 요소, SF 요소]

    예측: r̂(A, HP1) = u_A · v_HP1 (내적)
```

### 잠재 요인의 의미 (직관적 이해)

```
          SF 요소 높음
              ▲
              │       • 인터스텔라
              │    • 스타워즈
              │
   판타지 ◄───┼──────────────► 현실
   요소 높음  │            요소 높음
              │       • 기생충
              │  • 해리포터
              │
              ▼
          SF 요소 낮음

→ 비슷한 위치의 영화들끼리 유사한 잠재 벡터를 가짐
→ 사용자도 같은 공간에 표현됨
→ 가까울수록 높은 평점 예측!
```

### 학습 방법: RMSE 최소화

```
실제 평점과 예측 평점의 차이를 최소화!

RMSE = √(1/|E| × Σ (r̂_xi - r_xi)²)

      실제값  예측값  오차
r_11 =  5,   r̂_11 = 2  →  (5-2)² = 9
r_12 =  2,   r̂_12 = 2  →  (2-2)² = 0
r_21 =  3,   r̂_21 = 2  →  (3-2)² = 1

RMSE = √((9+0+1)/3) = √(10/3) ≈ 1.826
```

### Neural Collaborative Filtering (NCF)

기존 행렬 분해는 **내적(dot product)** 이라는 선형 연산 → 한계 존재  
→ **신경망**으로 비선형 복잡한 상호작용 학습!

```
입력층 (Sparse)
  [0,0,0,1,0,...] (사용자 one-hot)    [0,0,1,0,...] (아이템 one-hot)
        │                                      │
        ▼                                      ▼
  [사용자 임베딩]                         [아이템 임베딩]
        │                                      │
        └──────────────┬───────────────────────┘
                       │ (concatenate: 붙이기)
                       ▼
              [Neural CF Layer 1]
                       │
              [Neural CF Layer 2]
                       │
                    [Score ŷ]
                       │
              비교 ── [Target y] (실제 값)
```

## 6. 암묵적 피드백과 BPR 손실함수

### 문제 상황

```
Utility Matrix (암묵적):
  0 = "안 봤음"  (싫어서? 몰라서?)
  1 = "봤음"     (= 좋아함?)

→ 0을 "싫음"으로 학습하면 안됨!
  모든 안 본 영화를 추천 안 하도록 학습될 위험 (=> Ranking Loss의 아이디어로 발전)
```

### BPR (Bayesian Personalized Ranking) 해결책

> 절대적 점수 대신, **상대적 순서**를 학습하자!

```
사용자 u가 아이템 i를 봤고 (r_ui = 1): i = positive item
사용자 u가 아이템 j를 안 봤다면 (r_uj = 0): j = negative item

→ "u는 j보다 i를 더 좋아할 가능성이 높다"
→ ŷ_ui > ŷ_uj 가 되도록 학습!

BPR Loss = - Σ log σ(ŷ_ui - ŷ_uj)
              (u,i,j)

여기서 σ는 시그모이드 함수:
σ(x) = 1 / (1 + e^(-x))
```

### 시그모이드 함수

```
 σ(x)
  1.0 ─────────────────────╮
                      ╭────╯
  0.5 ─────────── ●  ─╯
              ╭───╯
  0.0 ───────╯────────────────── x
       -6  -4  -2   0   2   4   6

특성:
  - x = 0 일 때: σ(0) = 0.5
  - x가 크면: σ(x) → 1  (예측이 좋음)
  - x가 작으면: σ(x) → 0  (예측이 나쁨)
```

## 7. 그래프 기반 추천 (Advanced)

### 추천시스템을 그래프로 본다

```
Utility Matrix (기존 방식):

      아이템1  아이템2  아이템3
사용자A [  1  ][  0  ][  1  ]
사용자B [  0  ][  1  ][  1  ]
사용자C [  1  ][  1  ][  0  ]


그래프 표현 (같은 정보를 다르게!):

사용자A ───── 아이템1
사용자A ───── 아이템3
사용자B ───── 아이템2
사용자B ───── 아이템3
사용자C ───── 아이템1
사용자C ───── 아이템2

→ 이분 그래프 (Bipartite Graph): 사용자-아이템 간에만 엣지
```

### 그래프로 보면 새로 보이는 것들

```
K=2 경로 (2홉):
  사용자A ─ 아이템1 ─ 사용자C
  → A와 C는 아이템1을 공통으로 구매한 유사 사용자!

K=4 경로 (4홉):
  사용자A ─ 아이템1 ─ 사용자C ─ 아이템2 ─ 사용자B
  → A와 B는 2단계 연결 (간접적으로 유사한 취향)

기존 CF (1차 구조만 봄):
  "사용자A가 아이템1을 봤다" 만 활용

그래프 기반 (고차 구조 활용):
  A-B 간의 2홉, 4홉 경로도 임베딩에 반영!
  → 더 풍부한 정보 활용
```

## 8. 그래프 신경망 (GNN)

### GNN의 핵심 아이디어

> 노드의 표현을 학습할 때 **이웃 노드들의 정보도 함께** 반영한다

```
일반 신경망(MLP):
  입력 x → [W₁, b₁] → [W₂, b₂] → 출력
  (모든 노드가 독립적으로 처리)

GNN:
  노드 v
   ├── 이웃 A의 정보 ─┐
   ├── 이웃 B의 정보 ─┼──► [Aggregation] ──► 노드 v의 새 표현
   └── 이웃 C의 정보 ─┘

  "내 주변 이웃들의 정보를 모아서 나를 표현한다!"
```

### GNN Layer의 두 가지 연산

#### Step 1: Message (메시지 생성)

```
각 이웃 노드 u가 메시지를 만든다:

m_u^(l) = W^(l) × h_u^(l-1)
           ───────────────────
           (선형 변환 = 가중치 행렬로 변환)

이웃 A: h_A = [1, 2, 3]  →  W × [1,2,3] = [메시지_A]
이웃 B: h_B = [4, 0, 1]  →  W × [4,0,1] = [메시지_B]
이웃 C: h_C = [0, 3, 2]  →  W × [0,3,2] = [메시지_C]
```

#### Step 2: Aggregation (집계)

```
h_v^(l) = AGG({ m_u^(l) | u ∈ N(v) })

AGG 방법 선택:
  SUM:  메시지_A + 메시지_B + 메시지_C
  MEAN: (메시지_A + 메시지_B + 메시지_C) / 3
  MAX:  max(메시지_A, 메시지_B, 메시지_C) (element-wise)
```

#### Self-Connection (자기 자신도 포함!)

```
이웃만 보면 → 자기 자신의 이전 표현을 잃어버림!

해결: N(v) ∪ {v} = 이웃 + 자기 자신

h_v^(l) = AGG({ m_u^(l) | u ∈ N(v) ∪ {v} })
                                        ───
                                     자기 자신 추가
```

### L-Layer GNN = L-hop 이웃 참조

```
1-Layer GNN:           2-Layer GNN:
노드 v                  노드 v
 └── 직접 이웃만 봄       └── 직접 이웃
                            └── 그 이웃의 이웃까지 봄

                  ●  ← 2-hop
                 / \
              ●   ●  ← 1-hop
               \ /
                ●  ← target node (v)
```

### GCN (Graph Convolutional Network) 수식

```
h_v^(l) = σ( Σ    W^(l) × h_u^(l-1) / √(deg(v)+1)(deg(u)+1) )
             u∈N(v)∪{v}

핵심:
  - 이웃 수(degree)로 정규화 → 이웃이 많은 노드의 영향력 조절
  - σ: ReLU 등 비선형 활성화 함수

행렬 형태 (전체 그래프 한 번에):
  H^(l) = σ( D̃^(-1/2) Ã D̃^(-1/2) H^(l-1) W^(l) )
  
  Ã = A + I  (self-loop 추가된 인접행렬)
  D̃ = degree matrix of Ã
```

## 9. NGCF: Neural Graph Collaborative Filtering

### LFM의 한계

```
기존 잠재 요인 모델(LFM):
  score(u, v) = z_u · z_v  ← 1차 구조만!
  
  사용자 u와 아이템 v 사이의 직접 연결만 고려.
  그래프의 고차 연결 구조는 무시됨.

예시:
  u1 ─── v1 ─── u2 ─── v2 ─── u3
  (K=4 경로: u1과 u3는 간접적으로 유사한 사용자)
  
  → LFM은 이 관계를 임베딩에 직접 반영 못함!
```

### NGCF의 해결책

> GNN으로 임베딩을 전파시켜, **그래프 구조 정보가 담긴 임베딩** 생성

```
NGCF 전체 흐름:

Step 1. 초기 임베딩 설정
  모든 사용자/아이템에 임의의 학습 가능한 임베딩 부여
  E = [e_u1, e_u2, ..., e_v1, e_v2, ...]

Step 2. GNN으로 임베딩 전파
  레이어 1:  h^(1) = GNN_layer(E, A)
  레이어 2:  h^(2) = GNN_layer(h^(1), A)
  ...
  레이어 L:  h^(L) = GNN_layer(h^(L-1), A)

  → L번 반복할수록 L-hop 이웃 정보까지 반영!

Step 3. 최종 임베딩 획득
  z_u = h_u^(L)  (그래프 구조 반영된 사용자 임베딩)
  z_v = h_v^(L)  (그래프 구조 반영된 아이템 임베딩)

Step 4. 점수 계산 및 추천
  score(u, v) = z_u · z_v
  → 점수 높은 순으로 아이템 추천!
```

### NGCF 인접행렬 구조

```
           사용자들   아이템들
          ┌──────────┬──────────┐
사용자들  │    0     │    R     │
          ├──────────┼──────────┤
아이템들  │   R^T    │    0     │
          └──────────┴──────────┘

A = [[0, R], [R^T, 0]]  ← 이것이 GNN의 인접행렬

R_uv = 1이면 사용자 u가 아이템 v와 상호작용한 것
```

### NGCF의 파라미터 구성

```
┌─────────────────────────────────────────┐
│  NGCF 파라미터                           │
├──────────────────────┬──────────────────┤
│  Shallow Embedding   │  GNN 파라미터     │
│  O(D × |V|)          │  O(L × D²)       │
│                      │                  │
│  D = 임베딩 차원      │  L = GNN 레이어 수│
│  |V| = 노드 수        │  D = 임베딩 차원  │
└──────────────────────┴──────────────────┘
```

### 학습: BPR Loss + 역전파

```
학습 데이터 구성 (triplet):
  (u, i, j) 에서
    i = 사용자 u가 상호작용한 아이템 (positive)
    j = 상호작용 안 한 아이템 (negative, 랜덤 샘플링)

BPR Loss = - Σ log σ(z_u·z_i - z_u·z_j)
             (u,i,j)

목표: z_u·z_i > z_u·z_j 가 되도록!
     (u가 좋아하는 i의 점수 > 안 본 j의 점수)
```

## 10. 전체 요약 및 비교표

### 모델 발전 흐름

```
[시대별 추천 모델 발전]

1세대                2세대                    3세대
콘텐츠 기반           협업 필터링              딥러닝 기반
Content-based   →   Collaborative       →   Neural CF / GNN
                    Filtering

"아이템 특성           "비슷한 사람의             "그래프 구조 +
 분석"                 행동 참고"                 신경망 결합"
```

### 주요 모델 비교

| 모델 | 핵심 아이디어 | 입력 | Cold Start | 계산 비용 |
|------|-------------|------|-----------|---------|
| **Content-based** | 아이템 특성 유사도 | 아이템 메타데이터 | 사용자 OK, 아이템 OK | 낮음 |
| **User-User CF** | 유사 사용자 탐색 | Utility Matrix | 둘 다 취약 | 높음 |
| **Item-Item CF** | 유사 아이템 탐색 | Utility Matrix | 아이템 취약 | 중간 |
| **MF (UV분해)** | 잠재 요인 추출 | Utility Matrix | 아이템 취약 | 중간 |
| **NCF** | 신경망으로 상호작용 모델링 | Utility Matrix | 취약 | 높음 |
| **NGCF** | GNN으로 고차 구조 반영 | 상호작용 그래프 | 취약 | 매우 높음 |

### 각 상황별 추천 모델 선택 가이드

```
Q1. 아이템 메타데이터(설명, 장르 등)가 충분한가?
    ├── YES → Content-based 활용 가능
    └── NO  → CF / LFM 계열

Q2. 사용자-아이템 상호작용 데이터가 충분한가?
    ├── NO (새 서비스) → Content-based 우선
    └── YES
         ├── 빠른 추론 필요? → Item-Item CF
         ├── 정확도 중요?    → MF or NCF
         └── 최고 성능 필요? → NGCF (GNN 기반)

Q3. 새 아이템이 자주 추가되는가?
    ├── YES → Content-based or User-User CF
    └── NO  → Item-Item CF or LFM
```

### 핵심 개념 한눈에 정리

```
📌 Utility Matrix    : 사용자-아이템 평점 행렬 (sparse)
📌 Content-based     : 아이템 프로파일(특성) 기반 유사도 추천
📌 CF (User-User)    : 유사 사용자 탐색 → 미평가 아이템 점수 예측
📌 CF (Item-Item)    : 유사 아이템 탐색 → 더 안정적
📌 Matrix Factorizat.: Utility Matrix를 저차원 U, V로 분해
📌 NCF               : 내적 대신 신경망으로 상호작용 모델링
📌 BPR Loss          : 절대 평점 대신 상대 순위 학습 (implicit 피드백용)
📌 GNN               : 이웃 노드 정보를 반복 aggregation → 노드 임베딩
📌 NGCF              : GNN으로 사용자-아이템 그래프의 고차 구조 반영
```
