## Data 입력
### Tokenizer
* Token Id 생성
* BPE Tokenizer: GTP 계열에서 사용, fastest, 가장 많이 등장하는 쌍을 찾아서 추가
* Wordpiece Tokenizer: 각각으로 나올 확률보다 쌍으로 나올 확률이 높으면 추가
* Unigram Tokenizer: 각각의 글자 조합으로 최선의 조합을 찾고(score), 쓸모 없는 것은 버림. slowest

### 위치 Embedding
* 시퀀스의 길이에 관계없이 동일한 위치
* 절대위치 embedding: 삼각함수
* 상대위치 embedding: 단어와 단어 사이의 거리를 embedding,  속도가 느림
* ROPE: 위치와 각도에 비례하여 vector를 회전시키는 방식, 삼각함수 embedding보다 학습속도가 빠름 (절대위치, 상대위치 embedding의 장점만 사용)
  
## Text 생성
* prompt: 모델의 input
* special token: 모델을 제어하고, 입력/출력의 구조를 정의하는 제어 신호 (문장의 시작과 끝, 사용자 질문 시작, 시스템 프롬프트, CoT, 외부도구 호출 등을 나타내는 token)
* Token Embedding:
   * 입력과 출력은 길이가 같아야 함 (입력: "In" "the" "heart" "of" => 타겟(예측값): "the" "heart" "of" "the")
   * 실제 text들을 그대로 사용할 수 없으므로 token id들을 가지고 와서 embedding

## GPT
### Attention (<- Multihead Attention)
* 문맥을 파악하기 위함. 연관되어있으면, 값이 크게 나타남.
   * self-attention: 자기 자신과 비교, encoder에서 맨처음 호출될 때는 self-attention
   * cross-attention: 두 번째 이후...
   * Q, K, V: Question (질문을 하는 주체), Key (질문에 답하는 대상), Value (전달할 정보)..
      * embedding 결과에 weight을 곱해서 Q, K, V를 입력
      * K, V를 분리하지 않으면, key에 다른 값이 섞일 수 있음 
* _Attention Score (p.90): Attention(Q, K, V) = softmax(Q(K^T) / sqrt(d_k)) * V_
   * Q * (K^T) => MatMul
   * MatMul / sqrt(d_k) = Scale
   * Scale * V => softmax 연산으로 들어감 => MatMul이 되어 다음의 input (=> Attention(Q, K, V)으로 들어감) : (p.92)
