# AI RRC State Predictor — 상세 설계 · 구현 · 운영 가이드

> **구현 방식**: 시나리오 B (C++ 직접 포팅, GRU 기반, 외부 라이브러리 없음)
> **설계 원문**: `VCCB_AI_Integration_DetailedDesign.md` (본 문서는 구현 현황 + ML 파이프라인 + 운영 절차 통합본)
> **대상 독자**: VCCB 개발자 + Python/ML 입문자

## 0. 한눈에 보기

- **무엇을 하는가**: RRC_CONNECTED 상태의 UE를 RRC_INACTIVE로 보낼 때, **inactivity timer를 얼마로 줄지**와 **지금 INACTIVE로 보낼지/조금 더 연결을 유지할지**를 작은 신경망(GRU)이 추천한다.
- **AI가 내는 값 2가지**
  - `resume_prob` (0~1): "이 UE가 곧 다시 깨어날(resume) 확률". 높으면 → 연결 유지(INACTIVE 보류)가 유리.
  - `resume_time` (초): "다음에 깨어나기까지 예상 시간". 이 값으로 타이머를 정함 (`timer = resume_time × MARGIN`).
- **핵심 개입 1지점**: `FnVCCBAiClient_IsAbleToProceedInactive()` — InactivityNotification을 받았을 때 INACTIVE로 천이할지(=true) 보류할지(=false) 결정. `resume_prob ≥ 0.6`이면 보류하고 타이머를 연장.
- **안전장치**: 추론 실패/타임아웃이 누적되면 **Fallback**(기존 정적 타이머 로직)으로 자동 복귀. `g_aiEnabled=false`면 AI 결정을 완전히 끄고 legacy 동작.

## 1. 시스템 구조

### 1-1. GRU 모델 명세 (C++ 추론과 1:1 일치)

| 구성 | 사양 |
|---|---|
| 입력 1 (시퀀스) | `seq[10][2]` — 과거 최대 10회 resume 이력 (durationSec, resumeCause) |
| 입력 2 (정적) | `stat[15]` — 현재 호의 5QI/DRB/AMBR/RSRP/RNA/시각 등 |
| GRU | input_size=2, hidden_size=16, num_layers=1 (게이트 순서: reset \| update \| new) |
| MLP | Linear(15 → 16) + ReLU |
| 결합 | concat(GRU_out 16, MLP_out 16) = 32 |
| Head1 | Linear(32 → 1) + Sigmoid → `resume_prob` |
| Head2 | Linear(32 → 1) (선형) → `resume_time` |
| 총 파라미터 | **1,282개** |

> C++ 추론 엔진(`VccbAiEngine.cpp`)과 학습 모델(`train.py::RrcGruModel`)은 **구조·가중치 배열 레이아웃이 정확히 동일**해야 한다. 가중치는 `export_weights.py`가 `VccbAiWeights.h`로 내보낸다.

### 1-2. AI 개입 포인트 ①~⑤ (구현 완료)

| 포인트 | 위치 | 역할 | 상태 |
|---|---|---|---|
| **①** | `MsgE1apMake.cpp` → `VEIL_fillE1_Inactivity_Timer()` | E1AP BearerContext Setup/Modify 시 추천 타이머 주입 (`FnVCCBAiClient_RecommendInactivityTimer`) | ✅ |
| **②** | `FeatRrcInactive.cpp` → `FnVCCB_IsAbleToProceedRRCInactive()` | InactivityNotification 수신 시 즉시 INACTIVE 천이 vs 타이머 연장 판단. `false` 반환 시 `BearerContextModification` fire-and-forget 송신 | ✅ |
| **③** | `StateSaRrcInact.cpp` → `FnVCCB_Inact_ProcRRCResumeRequest1()` | RRCResume 수신 시 INACTIVE 지속시간·원인을 이력에 기록 (`FnVCCBAiClient_OnResumeRequest`) | ✅ |

## 3. 주요 상수 · 전역 통계 (`VccbAiClient.h`)

| 상수 | 값 | 의미 |
|---|---|---|
| `VCCB_AI_KEEP_THRESHOLD` | 0.6 | 이 값 이상이면 INACTIVE 보류(연결 유지) |

전역 통계(`VccbAiGlobalStats_type`, `FnVCCBAiClient_PrintStats()`로 출력): 총 요청/성공/실패/타임아웃/Fallback 수, 포인트별 호출 수, 평균 추론 시간, 연속 실패 수, Fallback 모드 여부.

### 5-2. `preprocess.py` (데이터 생성)

- **Method A (합성)**: 5QI별 3GPP 도메인 규칙(Log-Normal duration, RSRP/성공률 영향)으로 `N_SYNTHETIC`(기본 20000)개 샘플 생성. 학습 데이터의 본체.
- **Method B (gtest 실측)**: `VCCB_AI_DATA_FILE` CSV가 있으면 로드해 합성과 병합. 실제 `buildAiInput()`이 만든 feature 범위를 반영.
- 출력 시 `resume_prob=1 비율`, `resume_time mean/std`를 찍어 **라벨 균형**을 확인할 수 있다 (이상적 ~50%).
- 주요 조정 포인트: `N_SYNTHETIC`(env `VCCB_AI_SYNTH_N`), `PROB_HORIZON_SEC`(env `VCCB_AI_PROB_HORIZON`, 기본 60s), `FIVEQI_PROFILES`.

### 5-3. `train.py` (학습) — 정규화 fold 설계

raw feature는 스케일 편차가 크다(AMBR 10~2000, RSRP 0~127, duration 0~수백, 0/1 플래그…). 이를 그대로 넣으면 첫 Linear의 출력이 수백~수천이 되어 **sigmoid가 포화 → `resume_prob`이 입력과 무관하게 1.0으로 고정**되고 회귀도 붕괴한다.

**해결**: 학습은 정규화된 입력/타겟으로 하고, 그 정규화를 `export_weights.py`가 가중치에 되접어(fold) **C++은 여전히 raw 입력/raw 초 출력**을 쓰게 한다. (엔진·`buildAiInput()` 무수정)

- 고정 정규화 상수: `SEQ_MEAN/STD`(2), `STAT_MEAN/STD`(15), `TIME_MEAN/STD`. (도메인 기반, 데이터 의존 아님)
- `VccbDataset`에서 입력(seq/stat)·타겟(time) 정규화. `Y_prob`(0/1)은 그대로.
- **(v1.2.0)** `Y_time`을 `REG_CLIP_SEC=600`으로 클립 + 손실 `MSE → SmoothL1(Huber)` → 긴 꼬리 outlier가 시간 손실을 폭발시키지 않게 안정화.
- 하이퍼파라미터: EPOCHS=50, BATCH=256, LR=1e-3, Adam + CosineAnnealing.

### 5-4. `export_weights.py` (가중치 내보내기) — fold 수식

학습 모델은 정규화 공간에서 동작하므로, 아래를 첫 affine 층에 흡수한다:
- 입력: `W·((x-μ)/σ)+b = (W/σ)·x + (b − (W/σ)·μ)` → `GRU_WEIGHT_IH`/`GRU_BIAS_IH`, `MLP_WEIGHT`/`MLP_BIAS`
- 시간 출력 역정규화: `t = t_norm·σ_t + μ_t` → `HEAD_TIME_WEIGHT`/`HEAD_TIME_BIAS`
- `head_prob`(sigmoid 출력)과 `GRU_HH`는 **무변경**

수식이 정확히 동치라 C++ 결과는 학습과 일치한다. 실행 시 `Inference @feature-mean` 한 줄로 포화 여부를 자가 점검한다.

> ⚠ **`train.py`와 `export_weights.py`의 정규화 상수는 반드시 동일** (export가 train에서 import). 상수를 바꾸면 둘 다 재실행.

### 5-5. `run_all.sh`

`pip install -r requirements.txt` → `preprocess.py` → `train.py` → `export_weights.py`를 순서대로 실행하는 일괄 스크립트(`set -e`로 중간 실패 시 중단).

## 6. 학습 데이터 전략 (Method A + B) & 데이터 수집 로거

- 공개 데이터셋(Kaggle/HuggingFace 등)에는 gNB 내부 call-processing feature 조합이 없어 **의미가 불일치**한다 → 합성(A) + 실측(B)으로 자체 생성.
- **데이터 수집 로거** (`VccbAiClient.cpp`, `#ifdef VCCB_AI_DATA_COLLECT`): Resume 발생 시 history 갱신 **직전** `buildAiInput()`으로 feature 스냅샷 + 실측 레이블을 CSV 1행 emit. 운영 빌드에는 영향 없음(토글 OFF가 기본).
- CSV 스키마: `callId, seq0_dur, seq0_cause … seq9_dur, seq9_cause, stat0 … stat14, label_durationSec, label_resumeCause`
- 출력 경로: env `VCCB_AI_DATA_FILE` (기본 `/tmp/vccb_ai_dataset.csv`), append 모드.
- 빌드 토글: `VCCB/Makefile.body`, `VCCB/Test/ut/Makefile.body`에 `ifeq ($(VCCB_AI_DATA_COLLECT),1) → -DVCCB_AI_DATA_COLLECT` (기본 OFF).

## 8. 학습에서 일어나는 일 (Python/ML 입문자용)

학습은 "예측이 정답에 가까워지도록 가중치를 조금씩 고치는 것"의 반복이다.

### 8-1. 용어

- **샘플 / 데이터셋**: 한 줄(한 호의 feature + 정답)이 샘플. 전체를 학습용 85% / 검증용(Val) 15%로 나눈다.
- **epoch(에폭)**: 학습 데이터 **전체를 한 번 다 본 것**. 50 epoch = 50번 반복 학습.
- **batch**: 한 번에 256개씩 묶어 처리(메모리·속도 때문).
- **loss(손실)**: 예측이 정답과 **얼마나 틀렸는지**를 하나의 숫자로. **작을수록 좋다.**
- **gradient/optimizer(Adam)**: loss를 줄이는 방향으로 가중치를 조금씩 이동.

### 8-2. 출력 표의 각 열 의미

```
Epoch      Train        Val   P_loss   T_loss
   25     0.2868     0.2940   0.2857   0.0167 *
```

| 열 | 의미 | 좋은 방향 |
|---|---|---|
| **Epoch** | 몇 번째 전체 반복인지 | — |
| **Train** | 학습셋 평균 loss (= P_loss + 0.5×T_loss). 모델이 **학습 데이터**에 틀린 정도 | 감소 |
| **Val** | 검증셋(학습에 안 쓴 15%) 평균 loss. **처음 보는 데이터**에 대한 일반화 성능 → 가장 중요한 지표 | 감소 |
| **P_loss** | `resume_prob` 분류 손실(BCE). "곧 resume할지"를 맞히는 정확도 | 0에 가깝게 |
| **T_loss** | `resume_time` 회귀 손실(Huber, **정규화 단위**). resume_prob=1인 양수 샘플에서만 계산 | 작게 |
| **`*`** | 지금까지 중 **Val loss 최저(best)를 갱신**한 epoch. best 모델만 `model.pt`로 저장 | — |

### 8-3. 어떻게 읽나

- **`*`가 붙은 줄** = 그 epoch이 역대 최고 성능(Val 기준). `*`가 없는 줄 = 직전 best보다 안 좋아서 저장 안 함(요동/과적합 신호일 수 있음). 끝에서 best 모델을 다시 불러와 저장한다.
- **Train ≈ Val로 같이 감소하다 평평해짐** = 정상 수렴. Val이 다시 오르면 과적합.
- **Train이 수천~수백만으로 들쑥날쑥** = 입력 스케일/타겟 outlier 문제. 본 프로젝트는 **정규화(v1.1.0) + 타겟 클립·Huber(v1.2.0)**로 해결 → 현재는 0.3 부근에서 매끄럽게 수렴.
- **T_loss 정규화 단위 → 초 환산**: SmoothL1/MSE 값에 대략 `√loss × TIME_STD(60)` 정도가 시간 오차(초)의 감.

### 8-4. 정상 학습 예시(v1.2.0)

`resume_prob=1 비율 55.4%`(균형 OK), Train/Val 0.29 부근 매끄럽게 수렴, `export` 자가점검 `resume_prob≈0.69`(1.000 아님)·`resume_time≈37s`(현실적) → **포화 해소 + 안정 회귀** 확인.

- gtest **빌드/실행은 docker 안**(크로스컴파일 toolchain). p4 워크스페이스가 docker에 mount되어 docker에서 만든 `vccb_ai_dataset.csv`/`VccbAiWeights.h`가 호스트에도 그대로 보임(복사 불필요).

## 10. 스크립트 버전 관리 (`SCRIPT_VERSION`)

- `train.py` / `export_weights.py` 상단 `SCRIPT_VERSION`을 **기능 변경 때마다 bump** + 주석에 이력 한 줄.
- 실행 로그(`[train.py vX]`)와 생성 헤더(`// Scripts : ...`)에 박혀 **어떤 버전으로 만든 가중치인지 추적** 가능.
- 버전 이력:
  - `train.py`: `1.0.0`(raw) → `1.1.0`(입력·time 정규화) → `1.2.0`(타겟 클립 `REG_CLIP_SEC=600` + Huber)
  - `export_weights.py`: `1.0.0`(raw) → `1.1.0`(정규화 fold). v1.2.0은 학습측만 변경이라 export는 1.1.0 유지.
