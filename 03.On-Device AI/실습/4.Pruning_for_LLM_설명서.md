## 2. Pruning 개요 — 두 기법 비교

Pruning은 모델의 가중치(weight) 중 **"중요하지 않은" 값을 0으로 만들어** 희소(sparse)한 모델을 만드는 기법입니다.  
핵심은 **어떤 기준으로 "중요하지 않은 가중치"를 판단하느냐**에 있습니다.

```
┌─────────────────────────────────────────────────────────────────────┐
│                         Pruning 기법 비교                            │
│                                                                     │
│  ┌─────────────────────────┐     ┌─────────────────────────────┐   │
│  │  Magnitude-based Pruning│     │       Wanda Pruning          │   │
│  ├─────────────────────────┤     ├─────────────────────────────┤   │
│  │ 중요도 = |W|             │     │ 중요도 = |W| × ||X||₂        │   │
│  │                         │     │                             │   │
│  │ 가중치 절댓값이 크면      │     │ 가중치가 크고 + 그 열에      │   │
│  │ 중요한 가중치로 판단      │     │ 큰 activation이 곱해질수록   │   │
│  │                         │     │ 중요한 가중치로 판단          │   │
│  │ ▸ 데이터 불필요(빠름)    │     │ ▸ calibration data 필요      │   │
│  │ ▸ global threshold 적용  │     │ ▸ row-wise threshold 적용    │   │
│  │ ▸ 정확도 손실 큼         │     │ ▸ 정확도 손실 작음           │   │
│  └─────────────────────────┘     └─────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

> **직관적 이해**: 아무리 가중치 자체가 크더라도, 그 가중치와 곱해지는 입력(activation)이 항상 0에 가깝다면 출력에 미치는 영향은 거의 없습니다. Wanda는 이 점을 반영합니다.

## 3. 함수 1: `evaluate()` — 모델 성능 평가

### 역할

Pruning 전/후 모델의 성능 변화를 측정하기 위해 **Perplexity(PPL)** 를 계산합니다.

### Perplexity란?

$$\text{Perplexity} = \exp\left(-\frac{1}{N} \sum_{i=1}^{N} \log P(w_i | w_1, \ldots, w_{i-1})\right)$$

- **낮을수록 좋음**: 모델이 다음 토큰을 더 확신 있게 예측한다는 의미
- PPL = 10이면 → 다음 단어 후보를 10개 정도로 좁혔다는 직관적 해석 가능

### 코드 분석

```python
@torch.no_grad()  # 평가 시 gradient 계산 비활성화 → 메모리/속도 효율
def evaluate(model, tokenizer):
    # 1. WikiText-2 테스트셋 로딩 & 토크나이징
    testenc = load_dataset('Salesforce/wikitext', 'wikitext-2-raw-v1', split='test')
    testenc = tokenizer("\n\n".join(testenc['text']), return_tensors='pt')
    testenc = testenc.input_ids.to(model.device)

    nsamples = 40  # 전체 토큰을 2048 단위로 자른 청크 수
    model = model.eval()

    nlls = []
    for i in range(nsamples):
        # 2. 2048 토큰 단위로 배치 슬라이싱
        batch = testenc[:, (i * 2048):((i + 1) * 2048)].to(model.device)

        # 3. 모델 순전파
        lm_logits = model(batch).logits  # shape: [1, 2048, vocab_size]

        # 4. 다음 토큰 예측을 위해 시프트
        shift_logits = lm_logits[:, :-1, :]   # 예측: [0~2046번 토큰의 예측값]
        shift_labels = testenc[:, (i * 2048):((i + 1) * 2048)][:, 1:]  # 정답: [1~2047번 토큰]

        # 5. Cross-Entropy Loss = Negative Log-Likelihood
        loss = nn.CrossEntropyLoss()(
            shift_logits.view(-1, shift_logits.size(-1)),
            shift_labels.view(-1)
        )
        nlls.append(loss.float() * 2048)  # 청크 전체의 NLL

    # 6. 평균 NLL에 exp() 적용 → Perplexity
    return torch.exp(torch.stack(nlls).sum() / (nsamples * 2048))
```

### 핵심 흐름 도식

```
WikiText-2 전체 텍스트 (하나의 긴 문자열)
         │
         ▼ tokenizer()
[t0, t1, t2, ..., t_N]  (전체 토큰 시퀀스)
         │
         ▼ 2048 토큰씩 슬라이싱 (40회 반복)
┌──────────────────────┐
│ batch: [t0 ~ t2047]  │  → model forward → logits
│                      │
│  shift_logits = 예측  │  logits[:-1] → 0번 위치가 1번 토큰을 예측
│  shift_labels = 정답  │  input[1:]   → 실제 1번 토큰
└──────────────────────┘
         │
         ▼ CrossEntropyLoss × 2048
     NLL per chunk
         │
         ▼ 모든 청크 합산 후 / (40 × 2048) → exp()
       Perplexity
```

### shift_logits / shift_labels 이해

```
입력 토큰:  [A, B, C, D, E]   (indices 0~4)
logits:     [p_A→?, p_B→?, p_C→?, p_D→?, p_E→?]

shift_logits = logits[:-1] = [p_A→?, p_B→?, p_C→?, p_D→?]
shift_labels = tokens[1:]  = [B,     C,     D,     E    ]

즉, "A 다음에 B가 온다"는 예측이 얼마나 맞는지 CrossEntropy로 측정
```

## 4. 함수 2: `prune_magnitude()` — 크기 기반 Pruning

### 역할

모든 `nn.Linear` 레이어를 순회하며, **가중치 절댓값이 작은 순서대로** 지정한 비율(sparsity)만큼 0으로 만듭니다.

### 코드 분석

```python
@torch.no_grad()
def prune_magnitude(model, sparsity):
    for n, m in model.named_modules():
        # lm_head는 제외 (출력 임베딩 레이어 — 건드리면 성능 급락)
        if isinstance(m, nn.Linear) and "lm_head" not in n:
            W = m.weight.data  # 가중치 행렬, shape: [out_features, in_features]

            # 1. 제거할 원소 수 계산
            num_elements = W.numel()
            num_zeros    = round(num_elements * sparsity)  # e.g., sparsity=0.5 → 50% 제거

            # 2. 중요도 = 절댓값
            importance = torch.abs(W)  # shape: [out, in]

            # 3. num_zeros 번째로 작은 값을 임계값(threshold)으로 결정
            threshold = torch.kthvalue(importance.flatten(), num_zeros)[0]
            # kthvalue(tensor, k) → k번째로 작은 값 반환

            # 4. 임계값보다 큰 가중치만 True인 마스크 생성
            mask = importance > threshold  # shape: [out, in], dtype: bool

            # 5. 마스크 적용 (False 위치 → 0으로 만들기)
            W.mul_(mask)
```

### Pruning 과정 도식

```
가중치 행렬 W (예시: 4×4)
┌─────────────────────────────────┐
│  0.8  -0.1   0.3  -0.7          │
│  0.05  0.9  -0.4   0.2          │
│ -0.6   0.15  0.7  -0.03         │
│  0.4  -0.8   0.02  0.5          │
└─────────────────────────────────┘
        │
        ▼ torch.abs() → 중요도 행렬
┌─────────────────────────────────┐
│ 0.80  0.10  0.30  0.70          │
│ 0.05  0.90  0.40  0.20          │
│ 0.60  0.15  0.70  0.03          │
│ 0.40  0.80  0.02  0.50          │
└─────────────────────────────────┘
        │
        ▼ sparsity=0.5 → 상위 50% 제거
          16개 중 8개 제거, threshold = 8번째로 작은 값
        │
        ▼ mask = importance > threshold
┌─────────────────────────────────┐
│  T     F     F     T            │ (T=유지, F=제거)
│  F     T     T     F            │
│  T     F     T     F            │
│  F     T     F     T            │
└─────────────────────────────────┘
        │
        ▼ W.mul_(mask) → 마스크 False 위치를 0으로
┌─────────────────────────────────┐
│  0.8   0.0   0.0  -0.7          │
│  0.0   0.9  -0.4   0.0          │
│ -0.6   0.0   0.7   0.0          │
│  0.0  -0.8   0.0   0.5          │
└─────────────────────────────────┘
```

### 핵심 포인트

- **Global Threshold**: 레이어 전체 가중치를 하나의 풀(pool)로 보고 일괄 임계값 적용
- **`kthvalue(tensor, k)`**: 텐서를 오름차순으로 봤을 때 k번째 값 반환 — 즉 "하위 k개 제거"의 경계값
- **`W.mul_(mask)`**: in-place 연산으로 원본 메모리를 직접 수정 (언더스코어 `_` = in-place)
- **`lm_head` 제외**: 언어 모델의 출력 레이어는 pruning하면 토큰 예측 자체가 망가지므로 제외

## 5. 함수 3: `get_calib_dataset()` — 보정 데이터셋 준비

### 역할

Wanda Pruning에서 "어떤 가중치가 실제로 중요하게 쓰이는가"를 측정하려면, **실제 데이터가 모델을 통과할 때 어떤 activation이 발생하는지** 알아야 합니다.  
이 함수는 그 측정에 사용할 **calibration dataset**을 준비합니다.

### 코드 분석

```python
def get_calib_dataset(tokenizer=None, n_samples=256, block_size=512):
    # 1. Pile 검증 데이터셋 로드 & 셔플
    dataset = load_dataset("mit-han-lab/pile-val-backup", split="validation")
    dataset = dataset.shuffle(seed=42)

    samples = []
    n_run = 0
    for data in dataset:
        line = data["text"].strip()
        line_encoded = tokenizer.encode(line)

        # 2. block_size(512)보다 긴 샘플은 스킵
        #    → 모든 샘플이 동일한 최대 길이 이하가 되도록 필터링
        if len(line_encoded) > block_size:
            continue

        sample = torch.tensor([line_encoded])
        if sample.numel() == 0:
            continue

        samples.append(sample)
        n_run += 1
        if n_run == n_samples:  # 256개 샘플 수집 후 종료
            break

    # 3. 모든 샘플을 하나로 이어붙임 → dim=1 방향으로 concat
    cat_samples = torch.cat(samples, dim=1)  # shape: [1, total_tokens]

    # 4. 이어붙인 토큰을 block_size(512) 단위로 균등 분할
    n_split = cat_samples.shape[1] // block_size
    return [cat_samples[:, i*block_size:(i+1)*block_size] for i in range(n_split)]
```

### 데이터 준비 흐름 도식

```
Pile 데이터셋 (대규모 텍스트)
│
▼ 셔플 → 순서 랜덤화 (seed=42 고정, 재현성 보장)
│
▼ 토크나이징 후 512 토큰 이하인 샘플만 선택
│
▼ 256개 샘플 수집
[sample_1: shape(1, 200)]
[sample_2: shape(1, 312)]
[sample_3: shape(1, 89)]
      ...
[sample_256: shape(1, 150)]
│
▼ torch.cat(samples, dim=1)
[1, total_tokens]  (e.g., [1, 45000])
│
▼ 512 토큰 단위 균등 분할
[block_0: shape(1, 512)]
[block_1: shape(1, 512)]
[block_2: shape(1, 512)]
      ...
[block_n: shape(1, 512)]  ← 이것이 prune_wanda에 입력될 calibration samples
```

### 왜 calibration data가 필요한가?

```
Magnitude만 보는 경우의 문제점:
  가중치 W = 0.001 (매우 작음)
  하지만 이 뉴런의 activation X = 1000 (매우 큼)
  → 출력 기여 = W × X = 1.0  ← 사실 중요한 가중치!

Wanda 해결 방식:
  중요도 = |W| × ||X||₂
  → 가중치가 작더라도 큰 activation과 곱해지면 중요하다고 판단
```

## 6. 함수 4: `get_calib_feat()` — Activation Norm 수집

### 역할

Calibration 데이터를 모델에 통과시키면서, 각 `nn.Linear` 레이어의 **입력 activation의 L2 norm을 누적 평균**으로 수집합니다.  
이것이 Wanda pruning의 핵심 재료입니다.

### 전체 구조 이해

```
┌──────────────────────────────────────────────────────┐
│              get_calib_feat 전체 흐름                  │
│                                                      │
│  1. 모든 nn.Linear에 forward hook 등록               │
│     (레이어 실행될 때마다 add_batch 자동 호출됨)       │
│                                                      │
│  2. calibration samples를 모델에 순전파              │
│     → 각 Linear 레이어 통과 시 hook이 activation 수집 │
│                                                      │
│  3. 수집 완료 후 hook 제거                           │
│                                                      │
│  4. 누적된 값에 sqrt() 적용 → 최종 L2 norm          │
│                                                      │
│  결과: { "layer_name": tensor([norm_0, norm_1, ...]) }│
│         각 원소 = 해당 입력 차원의 평균 L2 norm        │
└──────────────────────────────────────────────────────┘
```

### 코드 분석 — `add_batch` (hook 함수)

```python
def add_batch(m, x, y, name):
    """
    Forward hook: 레이어가 실행될 때마다 호출됨
    m: 해당 모듈(Linear 레이어)
    x: 입력 (tuple 형태로 들어옴)
    y: 출력 (사용 안 함)
    name: 레이어 이름 (partial로 미리 바인딩됨)
    """
    # 초기화 (처음 호출 시)
    if name not in input_dict:
        input_dict[name] = torch.zeros(m.weight.data.shape[1], ...)  # shape: [in_features]
        nsamples_dict[name] = 0

    # 입력 전처리
    if isinstance(x, tuple):
        x = x[0]              # hook의 x는 항상 tuple → 첫 번째 원소가 실제 입력

    if len(x.shape) == 2:
        x = x.unsqueeze(0)    # [seq, hidden] → [1, seq, hidden]

    tmp = x.shape[0]          # 이번 배치의 샘플 수

    if len(x.shape) == 3:
        x = x.reshape(-1, x.shape[-1])  # [batch, seq, hidden] → [batch*seq, hidden]

    x = x.t()                 # [hidden, batch*seq]  ← 열(column)이 샘플이 됨

    # 누적 평균 업데이트 (incremental mean)
    input_dict[name] *= nsamples_dict[name] / (nsamples_dict[name] + tmp)
    nsamples_dict[name] += tmp

    x = x.type(torch.float32)

    # L2 norm 계산 (제곱 형태로 누적)
    activation_norm = torch.norm(x, p=2, dim=1) ** 2
    # dim=1 방향: 각 hidden 차원에 대해 배치 전체 샘플의 L2 norm 계산
    # shape: [hidden_size] = [in_features]

    input_dict[name] += activation_norm / nsamples_dict[name]
```

### 텐서 변환 흐름 도식

```
입력 x (Linear 레이어에 들어오는 activation)
shape: [batch=1, seq=512, hidden=576]
          │
          ▼ reshape(-1, hidden)
shape: [512, 576]    ← 512개 토큰, 각 576차원의 벡터
          │
          ▼ .t() (전치)
shape: [576, 512]    ← 576개 hidden 차원, 각 512개 토큰 샘플
          │
          ▼ torch.norm(x, p=2, dim=1)
          각 행(hidden 차원)에 대해 512개 샘플의 L2 norm 계산
          norm_i = sqrt(x[i,0]² + x[i,1]² + ... + x[i,511]²)
          │
          ▼ ** 2 (제곱으로 누적)
shape: [576]   ← 576개 hidden 차원 각각의 "activation 크기 지표"
          │
          ▼ (모든 calibration batch 처리 후) .sqrt_()
          ← 마지막에 한 번 제곱근을 취해 실제 L2 norm 복원
```

### 왜 제곱으로 누적하고 나중에 sqrt를 취하는가?

```
# 직접 L2 norm을 누적하면 올바른 평균이 되지 않음 (삼각 부등식 문제)
# 대신 분산의 누적 방식처럼 제곱값을 먼저 누적:

누적 중: input_dict[name] += (||x_i||₂²) / n  ← 제곱 norm의 평균
완료 후: input_dict[name].sqrt_()              ← 최종적으로 sqrt 적용

결과: √(평균(||x_i||₂²)) ≈ 각 hidden 차원의 RMS(Root Mean Square) activation norm
```

### Forward Hook 등록 방식

```python
hooks = []
for name, m in model.named_modules():
    if isinstance(m, nn.Linear) and "lm_head" not in name:
        hooks.append(
            m.register_forward_hook(
                partial(add_batch, name=name)  # name을 미리 고정
            )
        )

# calibration samples 순전파
for input_ids in samples:
    model(input_ids)  # 모델 통과 → 모든 Linear에서 hook 자동 실행

# 수집 완료 후 hook 제거 (메모리 누수 방지)
for hook in hooks:
    hook.remove()
```

## 7. 함수 5: `prune_wanda()` — Wanda Pruning

### 역할

가중치의 크기(magnitude)뿐 아니라 **해당 가중치와 곱해지는 입력의 크기**를 함께 고려하여 pruning합니다.  
또한 Magnitude-based와 달리 **행(row)별로 동일한 sparsity를 적용**합니다.

### 코드 분석

```python
@torch.no_grad()
def prune_wanda(model, sparsity, input_feat):
    for n, m in model.named_modules():
        if isinstance(m, nn.Linear) and "lm_head" not in n:
            W = m.weight.data  # shape: [out_features, in_features] = [row, col]

            row, col = W.shape

            # 1. 행별로 제거할 원소 수 계산
            num_zeros_per_row = round(col * sparsity)
            # e.g., col=576, sparsity=0.5 → 각 행에서 288개 제거

            # 2. Wanda 중요도 = |W| × ||X||₂
            importance = torch.abs(W) * input_feat[n]
            # input_feat[n]: shape [in_features] = [col]
            # broadcasting: [row, col] × [col] → [row, col]

            # 3. 행별 threshold 계산
            threshold = torch.kthvalue(importance, num_zeros_per_row, dim=1)[0]
            # dim=1: 각 행 내부에서 k번째로 작은 값
            # threshold.shape: [row]

            # 4. 행별 마스크 생성
            mask = importance > threshold.reshape(row, 1)
            # threshold를 [row, 1]로 reshape → broadcasting으로 [row, col]과 비교

            # 5. 마스크 적용
            W.mul_(mask)
```

### Magnitude vs Wanda — 중요도 계산 차이 도식

```
가중치 행렬 W (3×4 예시):         input_feat (열 방향, activation norm)
┌──────────────────────┐          ┌─────────────────────┐
│  0.8  -0.1   0.3  0.7│          │  0.1   1.0   0.5  0.2│  (각 입력 차원의 크기)
│  0.05  0.9  -0.4  0.2│          └─────────────────────┘
│ -0.6   0.15  0.7  0.03│

[Magnitude 중요도] = |W|:           [Wanda 중요도] = |W| × input_feat:
┌──────────────────────┐           ┌────────────────────────┐
│ 0.80  0.10  0.30  0.70│           │ 0.08  0.10  0.15  0.14 │
│ 0.05  0.90  0.40  0.20│           │ 0.005 0.90  0.20  0.04 │
│ 0.60  0.15  0.70  0.03│           │ 0.06  0.15  0.35  0.006│
└──────────────────────┘           └────────────────────────┘

Magnitude: W[0,0]=0.80 이 가장 중요   Wanda: W[1,1]=0.90 × 1.0 이 가장 중요
           W[1,0]=0.05 제거 후보                W[0,0]=0.80 × 0.1 = 0.08 → 낮은 중요도
                                              (큰 가중치지만 activation이 작아 덜 중요)
```

### Row-wise Pruning vs Global Pruning 비교

```
[Global Pruning (Magnitude)]
전체 가중치를 하나의 pool로 본 후 하위 50% 제거

W:  row0 [ 0.8,  0.05,  0.3,  0.6 ]
    row1 [ 0.1,  0.9,  -0.4,  0.2 ]
    row2 [-0.7,  0.15,  0.7,  0.03]

전체에서 50% 제거 → row2의 거의 모든 값이 살아남을 수도,
                     row0의 모든 큰 값이 살아남을 수도 있음
→ 특정 뉴런(행)이 완전히 0이 되거나, 전혀 안 줄어드는 불균형 발생 가능

[Row-wise Pruning (Wanda)]
각 행에서 독립적으로 50% 제거

W:  row0 [ 0.8,  0.0,  0.3,  0.0 ]   ← row0에서 2개 제거
    row1 [ 0.0,  0.9,  -0.4,  0.0 ]  ← row1에서 2개 제거
    row2 [-0.7,  0.0,  0.7,  0.0]    ← row2에서 2개 제거

→ 모든 출력 뉴런이 균등하게 일부 입력만 받게 됨
→ 특정 출력 채널이 완전히 죽는 현상 방지
```

### `threshold.reshape(row, 1)` Broadcasting 원리

```python
threshold = torch.kthvalue(importance, k, dim=1)[0]
# threshold.shape: [row]  e.g., [576]

mask = importance > threshold.reshape(row, 1)
# threshold.reshape(row, 1).shape: [576, 1]
# importance.shape:                [576, 576]
# broadcasting 비교: [576, 576] > [576, 1]
# → 각 행의 임계값이 해당 행 전체 열에 브로드캐스트되어 비교됨

# 시각화:
# threshold = [t0, t1, t2]  → reshape → [[t0],    비교 대상: [[a00, a01, a02],
#                                          [t1],                [a10, a11, a12],
#                                          [t2]]                [a20, a21, a22]]
# 결과: a_ij > t_i  (i번째 행의 모든 원소를 t_i와 비교)
```

## 9. Magnitude vs Wanda 비교 정리

| 구분 | Magnitude-based Pruning | Wanda Pruning |
|---|---|---|
| **중요도 기준** | `|W|` (가중치 절댓값) | `|W| × ‖X‖₂` (가중치 × activation norm) |
| **Threshold 적용 단위** | 레이어 전체 (global) | 행(row)별 독립적 |
| **Calibration 데이터** | 불필요 | 필요 (실제 activation 측정) |
| **구현 복잡도** | 낮음 | 중간 (hook, 누적 평균 필요) |
| **Perplexity 성능** | 상대적으로 높음 (나쁨) | 상대적으로 낮음 (좋음) |
| **핵심 아이디어** | 작은 가중치는 영향이 작다 | 출력 기여 = 가중치 × 입력 크기 |
| **참고 논문** | — | Sun et al., 2023 (arXiv:2306.11695) |

### Wanda 중요도 수식 정리

$$S_{ij} = |W_{ij}| \cdot \left\| \mathbf{X}_j \right\|_2$$

- $W_{ij}$: 행렬 W의 (i행, j열) 원소 → **j번째 입력 뉴런이 i번째 출력 뉴런에 연결되는 가중치**
- $\| \mathbf{X}_j \|_2$: j번째 입력 차원의 L2 norm → **이 입력이 얼마나 활발히 사용되는지**
- $S_{ij}$가 작을수록 → 해당 가중치가 출력에 미치는 실질적 영향이 작음 → Pruning 대상

---

> **정리**: Wanda는 추가적인 재학습(fine-tuning) 없이 단 한 번의 순전파(forward pass)만으로 activation 정보를 수집해, Magnitude-based pruning보다 훨씬 정확하게 "진짜 중요한 가중치"를 보존합니다. 이것이 LLM 시대에 Wanda가 주목받는 이유입니다.
